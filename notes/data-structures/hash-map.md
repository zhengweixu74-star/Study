## 哈希值、桶与相等规则

哈希函数根据键计算整数形式的哈希值。桶是哈希表中用于存放一组候选键值对的位置；实现根据哈希值和数组容量计算桶下标，再在对应桶内查找具体键。

相等的键必须产生相同的哈希值。不同的键也可能产生相同的哈希值，或者计算下标后进入同一个桶，这种情况称为哈希冲突。所以哈希值只用来缩小查找范围，最终仍要用相等规则比较键。

键存入表中后，参与哈希计算或相等比较的数据要保持不变。这些数据一旦改变，再次计算出的查找位置或比较结果就可能与存入时不同，键就查不到了。确需修改时，按容器的约定先移除旧键，再插入新键。

## 用链表处理冲突

链表由节点和指向后续节点的引用组成。每个节点可以保存哈希值、键、值和下一个节点的引用。多个键落到同一个桶时，桶记录链表起点，查找时沿链表逐个比较。

为了说明下标计算，假设哈希值为非负整数，用 `hash % capacity` 计算桶下标。容量为 8 时，键 A 的哈希值是 10，键 B 的哈希值是 18，两者都进入下标为 2 的桶。查找 B 时，程序还要比较候选节点的键，才能区分 A 和 B。实际实现常用哈希扰动和位运算代替直接取余。

| 操作 | 执行步骤 |
| --- | --- |
| 插入或更新 | 计算哈希值和桶下标 → 在桶内查找相等的键 → 找到则更新值；未找到则加入新节点 |
| 查找 | 计算哈希值和桶下标 → 比较桶内候选节点的哈希值与键 → 返回匹配值或报告不存在 |
| 删除 | 定位桶与匹配节点 → 修改桶起点或前一个节点的后续引用 → 从链表中移除该节点 |

## 负载因子与扩容

负载因子是已存键值对数量与桶数组容量的比值。负载因子超过阈值时，实现扩大桶数组，并按新容量重新分配节点。例如容量为 8、阈值为 0.75 时，条目数超过 6 后扩容。阈值和扩容规则由各实现自行决定。

沿用前面的取余示例，容量扩大到 16 后，A 的下标是 `10 % 16 = 10`，B 的下标是 `18 % 16 = 2`，原先同桶的两个键被分开。两个不同的键哈希值完全相同时，扩容后仍会落在同一个桶。重新分配位置时，实现可以复用节点中已保存的哈希值，无需再次调用键的哈希函数。

## 时间复杂度与实现边界

时间复杂度描述操作量随条目数 n 增大时的增长方式。在哈希计算和键比较可视为固定成本、哈希分布较均匀且负载受控的条件下，查找和删除的期望时间为 O(1)，插入的摊还期望时间为 O(1)。摊还指把偶尔扩容的成本平摊到一系列插入操作上；触发扩容的那次插入仍然较慢。

一次扩容通常需要处理现有条目，成本为 O(n)。在链表处理冲突的实现中，如果大量键进入同一个桶，查找可能退化为 O(n)。键是长字符串等复杂对象时，哈希计算和比较的成本也要单独计入。

桶数组加链表只是实现方式之一。有的实现在数组中探测空位；有的实现在满足条件时把过长的冲突链转换为树。所以“数组、链表和红黑树”只是部分实现的结构，各种阈值也只适用于对应的语言和版本。
