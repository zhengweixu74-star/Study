HashMap 是用哈希表实现的键值映射结构。键用于查找对应的值；同一个映射中，按照相等规则相同的键只对应一个值，不同键可以对应相同的值。对已有键再次赋值，通常会替换该键对应的旧值。普通 HashMap 不保证按插入顺序或排序顺序遍历。

Swift 的 `Dictionary` 提供相近的按键访问能力，例如 `ages["小明"] = 20`。这种使用方式的相似不表示 Swift 字典与其他语言的 HashMap 采用相同的内部结构。下面用“桶数组加链表”说明一种常见实现。

## 哈希值、桶与相等规则

哈希函数根据键计算整数形式的哈希值。桶是哈希表中用于存放一组候选键值对的位置；实现根据哈希值和数组容量计算桶下标，再在对应桶内查找具体键。

相等的键必须产生相同的哈希值；不同的键也可能产生相同的哈希值，或者在计算下标后进入同一个桶，这称为哈希冲突。因此，哈希值只能缩小查找范围，不能代替键的相等判断。

当键已经存入表中时，不应改变参与哈希计算或相等比较的数据。否则，再次计算出的查找位置或比较结果可能与存入时不同，导致无法正确查找。确需改变时，应按具体容器的约定先移除旧键，再插入新键。

## 用链表处理冲突

链表由节点和指向后续节点的引用组成。每个节点可以保存哈希值、键、值和下一个节点的引用。多个键落到同一个桶时，桶记录链表起点，查找时沿链表逐个比较。

为了说明下标计算，假设哈希值为非负整数，用 `hash % capacity` 计算桶下标。容量为 8 时，键 A 的哈希值是 10，键 B 的哈希值是 18，两者都进入下标为 2 的桶。查找 B 时，程序仍需比较候选节点的键，才能区分 A 和 B。实际实现可能使用哈希扰动和位运算，不一定直接取余。

| 操作 | 执行步骤 |
| --- | --- |
| 插入或更新 | 计算哈希值和桶下标 → 在桶内查找相等的键 → 找到则更新值；未找到则加入新节点 |
| 查找 | 计算哈希值和桶下标 → 比较桶内候选节点的哈希值与键 → 返回匹配值或报告不存在 |
| 删除 | 定位桶与匹配节点 → 修改桶起点或前一个节点的后续引用 → 从链表中移除该节点 |

## 负载因子与扩容

负载因子是已存键值对数量与桶数组容量的比值。实现可以在该比值超过阈值时扩大桶数组，并按新容量重新分配节点。例如容量为 8、阈值为 0.75 时，可在条目数超过 6 后扩容；这里是算法示例，不是所有 HashMap 的固定规则。

沿用前面的取余示例，容量扩大到 16 后，A 的下标是 `10 % 16 = 10`，B 的下标是 `18 % 16 = 2`，原先同桶的两个键可以分开。若两个不同键本来就具有相同的哈希值，扩大容量仍不能保证把它们分开。重新分配位置也不一定要求重新调用键的哈希函数；实现可以复用节点中已保存的哈希值。

## 时间复杂度与实现边界

时间复杂度描述操作量随条目数 n 增大时的增长方式。在哈希计算和键比较可视为固定成本、哈希分布较均匀且负载受控的条件下，查找和删除的期望时间为 O(1)，插入的摊还期望时间为 O(1)。摊还表示把偶尔扩容的成本分摊到一系列插入操作上，不表示每次插入都同样快。

一次扩容通常需要处理现有条目，成本为 O(n)。在链表处理冲突的实现中，如果大量键进入同一个桶，查找可能退化为 O(n)。长字符串等键的哈希或比较成本也应单独计入。

桶数组加链表只是实现方式之一。其他实现可以在数组中探测空位；部分实现会在满足条件时把过长的冲突链转换为树。因此，不能把“数组、链表和红黑树”当成所有 HashMap 的统一结构，也不能把某种实现的阈值推广到其他语言或版本。
