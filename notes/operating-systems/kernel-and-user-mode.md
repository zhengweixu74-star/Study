## 内核的职责

内核是操作系统中负责管理硬件资源、进程和访问权限的核心程序。内核是软件，CPU 和内存是内核管理的硬件；内核在 App 启动之前就已经运行。内核主要负责四类工作：

- 进程管理：维护进程及其编号、创建时间等信息。
- CPU 调度：从可以运行的线程中选择线程，为线程安排 CPU 执行机会。
- 内存管理：维护进程的地址空间与访问边界，阻止进程随意访问其他进程的内存。
- 资源访问控制：检查程序对受保护资源的访问权限。

App 可以通过系统接口向内核查询进程信息。查询在 App 运行期间进行，查到的信息可以是更早发生的事件，例如进程的创建时间。Apple 平台上的查询接口示例见 [Darwin、应用框架与系统服务](../ios/darwin-frameworks-and-services.md)。

## 用户态、内核态与系统调用

用户态和内核态是 CPU 执行代码时的两种权限级别：用户态代码只能访问自己进程的内存和普通指令，访问受保护的资源要请求内核；内核态代码可以直接访问受保护的资源。App 的代码运行在用户态。

系统调用是应用请求内核服务的入口：同一条线程从用户态进入内核执行内核代码，完成后再回到用户态。例如 App 读取文件时，线程通过系统调用进入内核，内核检查权限并读取数据，再带着结果回到用户态。

原子操作由 CPU 指令直接完成，在用户态执行，无需系统调用。所以只用原子操作反复尝试获取锁的纯用户态自旋锁，获取和等待都不进入内核，见[获取锁失败后的等待行为](../ios/threads-and-scheduling.md#获取锁失败后的等待行为)。

## 进入内核、线程阻塞与线程切换

进入内核态、线程阻塞和线程切换是三件不同的事：

| 事件 | 含义 |
| --- | --- |
| 进入内核态 | 线程通过系统调用、中断等途径开始执行内核代码 |
| 线程阻塞 | 线程暂停运行，等待某个条件满足 |
| 线程切换 | 调度器停下当前线程，改为在这个 CPU 上执行另一条线程 |

一次无需等待的系统调用，进入内核后直接返回，线程既没有阻塞，也没有切换。读取尚未到达的网络数据时，线程进入内核后阻塞，调度器再切换到另一条就绪线程，三件事依次发生。线程状态的定义见[并发、并行与线程状态](../ios/threads-and-scheduling.md#并发并行与线程状态)。
