# C++ 静态存储期对象与初始化

[返回笔记目录](../README.md)

分类：语言与运行时。本文区分 C++ 对象的存储期、作用域和初始化时机，并说明这些概念与应用启动的关系。

## 静态对象的含义

在讨论 C++ 启动初始化时，“静态对象”通常指具有静态存储期的类对象。静态存储期表示对象所用存储在程序运行期间一直存在。存储期说明存储持续多久；作用域说明名称可以在哪里使用；初始化时机说明何时把对象准备为可用状态。这三个概念需要分别判断。

命名空间作用域的全局对象、类的静态数据成员，以及函数内声明为 `static` 的局部对象，都可以具有静态存储期。全局对象即使没有显式写 `static`，也具有静态存储期。

静态数据成员属于类，而不是每个实例各有一份。静态成员函数可以不通过实例调用，但函数本身不是这里所说的“静态对象”。“静态”也不表示对象不可修改，更不等同于要求整个类只能创建一个实例的单例设计。

## 构造函数与初始化时机

构造函数是 C++ 类用于初始化对象的特殊函数。构造函数执行后，对象才能按照该类的初始化规则进入可用状态。可以用 Swift 的 `init` 辅助理解“初始化实例”的作用，但两种语言的具体初始化规则不同。

```cpp
struct Logger {
    Logger() {
        // 初始化这个 Logger 对象。
    }
};

Logger globalLogger;

void work() {
    Logger temporary;
    static Logger cached;
}
```

| 对象 | 存储与构造行为 |
| --- | --- |
| `globalLogger` | 具有静态存储期。常见 iOS 启动流程会在进入 `main` 前执行启动所需的这类非局部对象构造 |
| `temporary` | 具有自动存储期。每次执行到声明时构造，并在离开所在作用域时销毁 |
| `cached` | 具有静态存储期。此示例在第一次执行到声明时运行构造函数；初始化成功后，后续调用复用同一个对象 |

静态存储期不表示构造函数一定在 `main` 前运行。对于需要动态初始化的静态局部对象，第一次经过声明才执行初始化；如果程序始终没有执行到声明，就不会运行这次动态初始化。动态初始化是需要执行初始化代码才能完成的初始化，区别于加载程序前可确定的常量初始化。

C++ 语言还允许某些非局部对象的动态初始化延后。因此，描述 iOS 中常见的 pre-main 构造行为时，不能把这种常见实现推广为所有 C++ 静态对象的统一语言规则。

## 与应用启动的关系

pre-main 表示进入 `main` 之前的启动阶段。如果启动时必须构造的对象在构造函数中执行大量工作，这些工作会增加该启动阶段的耗时。函数内静态对象则需要根据首次执行声明的位置判断耗时归属，不能只看声明是否带有 `static`。

启动流程见 [iOS 应用启动、窗口与输入事件](../ios/app-lifecycle-and-events.md#main-之前的启动工作与-dyld)。静态库与动态库的区别见 [Xcode 工程管理与自动化测试](../engineering/xcode-and-testing.md#编译链接嵌入与装载)。对象具有静态存储期，与对象实现代码来自静态库还是动态库，是两个独立维度。
