# C++ 静态存储期对象与初始化

[返回笔记目录](../README.md)

本文区分 C++ 对象的存储期、作用域和初始化时机，并说明这些概念与应用启动的关系。

## 静态对象的含义

在讨论 C++ 启动初始化时，“静态对象”通常指具有静态存储期的类对象。静态存储期表示对象所用存储在程序运行期间一直存在。这里有三个互相独立的概念：存储期说明对象的存储存在多久；作用域说明对象的名称在哪些代码中可以使用；初始化时机说明对象在什么时候被构造为可用状态。

命名空间作用域的全局对象、类的静态数据成员，以及函数内声明为 `static` 的局部对象，都可以具有静态存储期。全局对象即使没有显式写 `static`，也具有静态存储期。

静态数据成员属于类，整个程序只有一份，不是每个实例各有一份。静态成员函数可以不通过实例调用，但函数不是对象，不属于“静态对象”。“静态”只描述存储期：静态对象可以被修改，也与“一个类只能有一个实例”的单例模式无关。

## 构造函数与初始化时机

构造函数是 C++ 类中负责初始化对象的特殊函数，构造函数执行完，对象才进入可用状态。构造函数的作用类似 Swift 的 `init`，但两种语言的初始化规则不同。

```cpp
struct Logger {
    Logger() {
        // 初始化这个 Logger 对象。
    }
};

Logger globalLogger;

void work() {
    Logger temporary;
    static Logger cached;
}
```

| 对象 | 存储与构造行为 |
| --- | --- |
| `globalLogger` | 具有静态存储期。常见 iOS 启动流程会在进入 `main` 前执行启动所需的这类非局部对象构造 |
| `temporary` | 具有自动存储期。每次执行到声明时构造，并在离开所在作用域时销毁 |
| `cached` | 具有静态存储期。此示例在第一次执行到声明时运行构造函数；初始化成功后，后续调用复用同一个对象 |

具有静态存储期的对象，构造函数不一定在 `main` 之前运行。动态初始化是指需要运行代码（例如构造函数）才能完成的初始化；与之相对的常量初始化，在程序加载前就能确定结果。需要动态初始化的静态局部对象，在程序第一次执行到声明时才初始化；程序始终没有执行到声明，就始终不初始化。

对于全局对象这类非局部对象，C++ 标准也允许把动态初始化推迟到 `main` 之后。iOS 上的实现通常在 `main` 之前完成构造，但这是常见实现，不是 C++ 标准对所有静态对象的统一要求。

## 与应用启动的关系

pre-main 是指进入 `main` 之前的启动阶段。在 pre-main 阶段构造的全局对象，如果构造函数做了大量工作，就会增加启动耗时。函数内的静态对象则在第一次执行到声明时构造，耗时算在第一次调用这个函数的地方。

启动流程见 [iOS 应用生命周期、启动与窗口](../ios/app-lifecycle-and-events.md#main-之前的启动工作与-dyld)。静态库与动态库的区别见 [Xcode 工程管理与自动化测试](../engineering/xcode-and-testing.md#编译链接嵌入与装载)。注意“静态存储期”与“静态库”无关：对象是否具有静态存储期，与对象的代码来自静态库还是动态库互不影响。
