# iOS 内存泄漏与无用对象排查

[返回笔记目录](../README.md)

排查分三步：先确定对象应该在什么时候释放，再找出超过这个时机仍然存活的对象，最后追踪哪些强引用让对象继续存活。总内存大小和 Leaks 的报告只是辅助证据。

强引用是会保持目标对象存活的对象引用。ARC、引用环与可达性的基本规则见 [ARC 与 Android GC](../language/swift-memory-and-references.md#arc-与-android-gc引用计数可达性与引用环)；本文说明如何取得运行时证据。

## 1. 确定对象的预期释放时机

预期释放时机是指：按照功能设计，对象已经完成用途、所有正常的持有关系都应该结束的时机。确定了预期释放时机，才能判断对象在这个时机之后仍然存活是否异常。

以通过导航控制器打开的页面为例，先确认以下条件：

- 页面已经移出导航栈，不再由导航控制器保存。
- 页面切换动画已经结束，页面发起的网络请求、定时器等任务已经完成或已清理。
- 功能没有缓存或复用该页面实例的设计。

在页面的 `deinit` 中打印类名和实例标识。`deinit` 是 Swift 类实例销毁前自动执行的方法；实例标识用于区分同一个类的不同对象。打印出的日志说明对应的页面实例已经开始销毁。

`viewDidDisappear` 只表示页面的视图已经从屏幕上消失，页面可能只是被新页面遮住，仍在导航栈中。所以判断页面是否该释放，要以上面的条件为准。没有看到 `deinit` 日志时，页面仍被某个对象强引用，原因可能是循环引用，也可能是单向的长期持有，需要继续检查持有关系。

## 2. 重复操作并筛选持续存活的对象

Allocations 是 Instruments 中记录内存分配的工具，可以查看分配数量、大小和存活情况。Mark Generation 按标记时刻划分分配区间，用来筛选某轮操作期间创建的对象。

1. 开始 Allocations 录制，进入即将执行目标功能的页面，点击 Mark Generation。
2. 执行“进入页面 → 执行功能 → 退出页面”，等第 1 节的预期释放条件都成立后，再点击 Mark Generation。
3. 重复相同操作。每轮区间中，检查本轮新建、观察时仍然存活的对象。
4. 按类名筛选目标对象，比较每轮结束后的存活数量，并检查各轮留下的实例。

例如每退出一次页面，`DetailViewController` 的存活数量就增加一个，说明页面实例在持续累积。接着要确认这些实例是否属于设计中的缓存。区间内也会发生与目标功能无关的内存分配，只有超过预期释放时机仍存活的目标对象才需要追查。

## 3. 用 Memory Graph 追踪强引用

Memory Graph 是某一时刻对象、内存分配及其引用关系的快照。页面退出并满足预期结束条件后，在 Xcode 中点击 Debug Memory Graph，搜索页面类名，选中仍然存活的实例。

查看指向这个页面实例的引用，确认每条引用的类型和来源对象，再沿强引用逐级找到持有方。Memory Graph 中的连线和对象名称只是线索，具体是哪个属性或闭包在持有页面，要结合引用详情和源码确认。

例如，检查得到以下强引用链：

`全局管理器 → 保存的回调闭包 → 页面`

这条引用链表示：全局管理器保存了回调闭包，回调闭包又强引用页面。这里没有引用环，但全局管理器一直存活，页面也就一直存活。Memory Graph 只展示引用关系；页面是否还需要保留，要依据功能设计判断。

## 4. 区分创建位置、持有原因与 Leaks 的范围

分配调用栈是创建某块内存时记录的函数调用路径。分配调用栈回答“对象在哪里创建”，引用关系回答“对象为什么仍然存活”，排查时两种证据都需要。

| 证据 | 能回答的问题 | 判断边界 |
| --- | --- | --- |
| Allocations 中的分配调用栈 | 哪条调用路径创建了目标对象？ | 创建对象的代码和当前持有对象的代码可能不同。 |
| Memory Graph 中的强引用关系 | 快照时哪些对象仍在持有目标对象？ | 是否属于不必要的持有，需要结合预期释放时机判断。 |
| Leaks 扫描结果 | 是否检测到已分配但不可达的内存？ | 仍可通过管理器、数组或缓存访问到的无用对象，Leaks 不会报告。 |

“不可达”指从程序仍可访问的起点（如全局变量、栈上的变量）沿引用找不到这块内存。还能访问到、但功能已经不需要的对象，同样持续占用内存，而 Leaks 不报告这类对象。所以 Leaks 没有报告问题时，仍要用 Allocations 和 Memory Graph 检查无用对象。

## 5. 修正持有关系并重复验证

在实际的持有方解除不再需要的引用。例如，管理器保存的回调只服务当前页面时，页面在不再需要回调时（如离开页面时）取消注册，并确认管理器删除了保存的闭包。取消注册要放在 `deinit` 之前的时机：管理器通过闭包强引用页面期间，页面不会销毁，`deinit` 中的取消注册代码永远不会执行。

证据显示存在循环强引用时，根据每个对象需要存活多久，调整闭包的捕获方式，或者在明确的结束时机断开引用。`weak` 引用不保持对象存活，功能仍然需要的持有关系要保留为强引用。

1. 使用相同操作、结束条件和观察方式复测。
2. 确认预期释放的目标实例执行了 `deinit`。
3. 确认同类对象的存活数量不再逐轮增加；存在预期缓存时，按缓存设计核对保留范围。
4. 必要时重新生成 Memory Graph，确认不合理的强引用已经解除，同时验证功能仍然正常。

总内存曲线只作为辅助证据。对象释放后，内存分配器或框架可能保留这部分存储以便复用，所以每次退出页面后，总内存可能不会回到进入页面前的数值。对象释放与缓存持有的具体例子见 [图片缓存、视图引用与释放](image-loading-decoding-and-memory.md)。
