# iOS 内存泄漏与无用对象排查

[返回笔记目录](../README.md)

先确定对象应该在什么时候释放，再找出超过预期时机仍然存活的对象，最后追踪哪些强引用使对象继续存活。总内存大小和 Leaks 的报告只能提供部分证据。

本文记录通用检查流程。强引用是会保持目标对象存活的对象引用。ARC、引用环与可达性的基本规则见 [ARC 与 Android GC](../language/swift-basics.md#arc-与-android-gc引用计数可达性与引用环)；这里重点说明如何取得运行时证据。

## 1. 确定对象的预期释放时机

预期释放时机是指：按照功能设计，对象已经完成用途，所有合法的持有关系都应该结束的时机。必须先确定这个条件，才能判断对象持续存活是否异常。

以通过导航控制器打开的页面为例，先确认以下条件：

- 页面已经移出导航栈，不再由导航控制器保存。
- 页面切换动画已经结束，相关任务已经完成或结束清理。
- 功能没有缓存或复用该页面实例的设计。

在页面的 `deinit` 中记录类名和实例标识。`deinit` 是 Swift 类实例销毁前自动执行的方法；实例标识用于区分同一类的不同对象。日志可以确认哪个页面实例已经开始销毁。

`viewDidDisappear` 只表示页面的视图已经消失。页面可能只是被其他页面遮住，因此不能把这个回调当作页面必须释放的依据。未看到 `deinit` 日志也不能直接证明存在循环引用，应继续检查持有关系。

## 2. 重复操作并筛选持续存活的对象

Allocations 是 Instruments 中记录内存分配的工具，可以查看分配数量、大小和存活情况。Mark Generation 按标记时刻划分分配区间，用来筛选某轮操作期间创建的对象。

1. 开始 Allocations 录制，进入准备执行目标功能的状态，并点击 Mark Generation。
2. 执行“进入页面 → 执行功能 → 退出页面”，等待第一步约定的结束条件成立，再点击 Mark Generation。
3. 重复相同操作，按每轮区间检查新建、但在观察时仍然存活的对象。
4. 按类名筛选目标对象，比较每轮结束后的存活数量，并检查各轮留下的实例。

例如每退出一次页面，`DetailViewController` 的存活数量就增加一个，这表示有持续保留的线索。还需要确认这些实例是否属于预期缓存。区间内也可能发生无关的内存分配，不能把所有存活对象都判定为异常。

## 3. 用 Memory Graph 追踪强引用

Memory Graph 是某一时刻对象、内存分配及其引用关系的快照。页面退出并满足预期结束条件后，在 Xcode 中点击 Debug Memory Graph，搜索页面类名，选中仍然存活的实例。

检查指向该实例的引用，确认引用类型和来源对象，再沿强引用向持有方追踪。需要结合引用详情和源码确认属性或闭包的持有关系，不能仅凭连线或对象名称判断。

例如，检查得到以下强引用链：

`全局管理器 → 保存的回调闭包 → 页面`

这表示管理器保存闭包，闭包又强引用页面。即使没有形成引用环，长期存活的管理器仍然可能使已经不需要的页面继续存活。工具展示的是引用关系；页面是否还需要保留，必须依据功能设计判断。

## 4. 区分创建位置、持有原因与 Leaks 的范围

分配调用栈是创建某块内存时记录的函数调用路径。分配调用栈回答“对象在哪里创建”，引用关系回答“对象为什么仍然存活”，两者不能互相替代。

| 证据 | 能回答的问题 | 判断边界 |
| --- | --- | --- |
| Allocations 中的分配调用栈 | 哪条调用路径创建了目标对象？ | 创建对象的代码不一定是当前持有对象的代码。 |
| Memory Graph 中的强引用关系 | 快照时哪些对象仍在持有目标对象？ | 是否属于不必要的持有，需要结合预期释放时机判断。 |
| Leaks 扫描结果 | 是否检测到已分配但不可达的内存？ | 仍可通过管理器、数组或缓存访问的无用对象，不能依赖 Leaks 自动发现。 |

这里的“不可达”指无法从程序仍可访问的起点沿引用找到该内存。仍可访问但功能已不再需要的对象，也会持续占用内存。因此，Leaks 没有报告问题，不等于已经排除无用对象的保留。

## 5. 修正持有关系并重复验证

根据实际持有方解除不再需要的关系。例如，管理器保存的回调只服务当前页面时，在页面结束使用回调的时机取消注册，并确认管理器移除了保存的闭包。不能只把这项清理写在页面的 `deinit` 中：如果管理器仍通过闭包强引用页面，页面就无法执行 `deinit`。

如果证据显示存在循环强引用，根据对象需要存活的时间调整闭包捕获方式，或在明确的结束时机断开引用。`weak` 不维持对象存活；不要为了消除引用环而削弱功能仍然需要的持有关系。

1. 使用相同操作、结束条件和观察方式复测。
2. 确认预期释放的目标实例执行了 `deinit`。
3. 确认同类对象的存活数量不再逐轮增加；存在预期缓存时，按缓存设计核对保留范围。
4. 必要时重新生成 Memory Graph，确认不合理的强引用已经解除，同时验证功能仍然正常。

总内存曲线只作为辅助证据。对象释放后，内存分配器或框架仍可能保留可复用的存储，因此不能要求每次退出页面后总内存立即恢复到完全相同的数值。对象释放与缓存持有的具体例子见 [图片缓存、视图引用与释放](image-loading-decoding-and-memory.md)。
