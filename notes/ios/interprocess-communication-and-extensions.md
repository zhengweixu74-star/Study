# iOS 进程间通信与应用扩展

[返回笔记目录](../README.md)

## 进程间通信与访问边界

进程是操作系统为运行程序创建的运行实例，拥有相应的内存地址空间和资源。进程间通信（IPC）指不同进程交换数据或发送事件。普通 Swift 对象和全局变量不能直接由另一个进程访问。

沙箱是系统限制进程访问文件、资源和系统服务的机制。iOS App 能使用哪种通信方式，取决于双方的权限、系统版本、扩展类型和运行状态。共享数据、发送通知、建立连接和唤醒进程是不同的能力。

| 方式 | 主要用途 |
| --- | --- |
| URL Scheme / Universal Links | 请求打开另一个 App，并传递少量参数 |
| App Groups | 让获得同一组权限的 App 和扩展通过共享存储交换数据 |
| Darwin 通知 | 跨进程通知某个事件发生，常配合共享存储使用 |
| Keychain Sharing | 在具有相同访问组权限的 App 之间共享密码、令牌等凭据 |
| UIPasteboard | 在 App 之间传递用户复制、粘贴的内容 |
| Socket | 在获得运行时间的进程之间直接发送和接收数据 |
| 系统扩展接口与 XPC | 在系统支持的扩展流程中传递输入、请求和结果 |

## App Extension 与主 App

App Extension（应用扩展）是随 App 一起安装、由系统在特定场景下运行的功能程序，用于在主 App 之外提供某项能力。主 App 是用户点击桌面图标后打开的完整应用。

| 扩展类型 | 作用 |
| --- | --- |
| 分享扩展 | 在其他 App 的分享界面中接收网页、图片或文件 |
| 小组件扩展 | 向主屏幕、锁定屏幕等位置提供小组件内容 |
| 通知服务扩展 | 在符合条件的远程通知展示前修改通知内容，或下载附件 |

以笔记 App 的分享扩展为例：

1. 用户在 Safari 中点击分享，并选择笔记 App 的分享操作。
2. 系统运行分享扩展，并向分享扩展提供网页链接等输入。
3. 分享扩展保存内容，并向系统报告本次任务完成。笔记 App 的主程序可以全程没有运行。

包含扩展并随扩展一起安装的 App 称为 containing app；发起扩展请求的 App 称为 host app。上例中，笔记 App 是 containing app，Safari 是 host app。两者不一定是同一个 App。

扩展代码运行在与主 App 不同的进程中。主 App 和扩展不能直接读取对方的普通内存变量；需要使用共享存储或系统允许的通信接口交换数据。扩展的启动、执行时间和结束受系统控制，不能把扩展理解为随时运行的后台线程。

Swift 的 `extension` 是为类型补充功能的语言语法。App Extension 是独立运行的功能程序。两者名称相近，但含义不同。

## URL Scheme 与 Universal Links

URL Scheme 是 URL 中用于标识处理方式的部分，例如 `myapp://detail?id=123` 中的 `myapp`。App B 注册自定义 Scheme 后，App A 可以请求系统打开对应 URL；系统将 URL 交给匹配的 App，接收方解析参数并执行操作。

Universal Links 是与 App 建立关联的 HTTP/HTTPS 链接。满足系统的打开条件时，系统将链接交给关联 App；目标 App 未安装时，可以由浏览器打开对应网页。开发者需要配置网站和 App 的关联。

这两种方式适合打开目标页面并携带少量参数。例如接收方解析 `id=123` 后显示编号为 123 的详情。URL 跳转通常涉及切换 App，不是供两个进程持续收发数据的连接。接收方需要验证参数，不能直接信任传入内容。

## App Groups 与共享数据的存储位置

App Groups 是系统为同一开发团队的 App 和扩展提供的分组授权能力。加入同一个组的成员可以访问该组的共享容器。共享容器是系统单独创建、允许组内成员访问的数据目录。

通过共享文件、数据库和持久化配置交换的数据保存在磁盘上。App Group 共享目录独立于主 App 和扩展各自的私有数据目录；扩展不会因此获得主 App 全部私有文件的访问权限。

| 目录 | 通常的访问范围 |
| --- | --- |
| 主 App 的私有数据目录 | 主 App 可以访问；扩展不能直接访问 |
| 扩展的私有数据目录 | 扩展可以访问；主 App 不能直接访问 |
| App Group 共享目录 | 具有同一 App Group 权限的主 App、扩展或其他 App 可以访问 |

文件和数据库可以放入共享目录。程序通过 `FileManager.default.containerURL(forSecurityApplicationGroupIdentifier: "group.com.example.app")` 获取该目录的 URL，不应硬编码系统分配的磁盘路径。前提是当前 App 或扩展已正确配置该 App Group；获取结果是可选值。

少量配置可以通过 `UserDefaults(suiteName: "group.com.example.app")` 访问该组的共享配置存储。主 App 和扩展必须使用同一个已授权的组标识。普通的 `UserDefaults.standard` 不会因此自动成为双方的共享配置。

共享配置不是共同持有一个 Swift 对象。UserDefaults 还可能涉及缓存和异步持久化，因此不能把设置值后立即发送通知理解为跨进程数据必然已经同步可见。

例如，分享扩展把图片保存到共享目录。用户之后启动主 App，主 App 从同一个目录读取图片，不需要分享扩展继续运行。多个进程同时修改同一份文件或数据库时，需要协调读写，避免相互覆盖或读到不完整内容。

## Darwin 通知与共享存储的配合

Darwin 通知是跨进程的事件通知。进程 A 发布一个通知名称，订阅该名称的进程 B 在具备执行条件时收到事件，并运行已注册的回调。回调是接收方预先提供、由通知机制在事件到达时调用的函数或闭包。

通过 `CFNotificationCenterGetDarwinNotifyCenter()` 使用 Darwin 通知时，不能通过 `userInfo` 携带业务数据。常见做法是先保存共享数据，再发送“数据已更新”的通知；接收方收到通知后重新读取共享状态。

1. 进程 A 按所选存储机制的规则完成共享数据写入，保证读取方能够取得完整数据。
2. 进程 A 发布双方约定的 Darwin 通知名称。
3. 具备执行条件的进程 B 收到通知后，从共享存储读取当前状态。

Darwin 通知不是逐条可靠保存消息的队列，也不能唤醒已被系统暂停执行的 App，或启动已经结束运行的 App。主 App 下次运行时仍需要主动读取共享状态，不能只依赖通知恢复状态。

`NotificationCenter.default` 只在当前进程内传递通知。即使两个进程使用相同的通知名称，普通 NotificationCenter 也不会自动建立跨进程通知关系。

## Socket、文件系统路径与实际数据传递

Socket 是操作系统提供的数据收发端点。端点是进程用于发送或接收数据的通信对象。双方通过 Socket 传递字节，再按照事先约定的格式解释这些字节。

UNIX domain socket 用于同一设备内的进程通信。这里讨论使用文件系统路径标识的 Socket；在 iOS App Group 场景中，这个路径需要位于组内成员都能访问的共享目录。

路径示意为 `<App Group 共享目录>/ipc.sock`。这里的路径是通信入口在文件系统中的地址；`ipc.sock` 是用于标识 Socket 的特殊文件条目。扩展通过这个地址找到要连接的主 App Socket。

以需要建立连接的流式 Socket 为例，流式表示双方收发的是连续字节序列：

1. 主 App 创建 Socket，并调用 `bind`，传入包含共享目录路径的地址，将 Socket 与该地址关联。
2. 主 App 调用 `listen`，允许其他进程向这个 Socket 发起连接。
3. 扩展创建自己的 Socket，调用 `connect` 并传入同一个地址。操作系统根据路径找到主 App 的 Socket。
4. 主 App 调用 `accept` 接收连接，并获得用于本次连接的 Socket。连接建立后，双方通过连接对应的 Socket 发送和接收数据。

Socket 路径用于找到通信对象。通过 Socket 发送的消息由操作系统在内存中传递，不会作为 `ipc.sock` 的普通文件内容写入磁盘。共享目录提供地址所在的位置和访问权限，不表示消息通过读写普通文件完成传输。

| 比较项 | 共享普通文件 | UNIX domain socket |
| --- | --- | --- |
| 路径的含义 | 定位保存数据的文件 | 定位用于连接的通信入口 |
| 数据传递方式 | 发送方写文件，接收方读文件 | 双方通过 Socket 发送、接收字节 |
| 数据是否保存在该路径对应的普通文件内容中 | 是 | 否 |
| 发送方结束运行后能否再读取先前数据 | 文件仍存在且可访问时可以 | 不能把 Socket 当作持久化消息存储 |

双方需要获得运行时间才能执行收发逻辑。建立 Socket 连接本身不能让 iOS App 持续在后台运行；Socket 路径仍存在，也不代表对应进程或连接仍然可用。

## 凭据共享、剪贴板与系统扩展接口

### Keychain Sharing

Keychain 是系统提供的敏感数据存储服务。钥匙串访问组规定哪些 App 可以访问某个钥匙串条目。同一开发团队的 App 配置相同的访问组后，可以共享属于该组的密码、令牌或密钥。

例如 App A 将登录令牌写入共同的访问组，App B 在具有相应权限时读取该令牌。Keychain Sharing 适合共享凭据，不适合频繁发送普通业务消息。

### UIPasteboard

`UIPasteboard` 是访问系统剪贴板的接口。App A 写入文本、链接或图片，App B 读取这些内容。剪贴板适合用户主动复制、粘贴；内容可能被后续复制操作覆盖。程序读取其他 App 写入的内容可能触发授权提示，因此不适合作为持续、自动的通信通道。

### NSExtensionContext 与 XPC

对于分享扩展等系统规定的扩展流程，调用方提供输入，扩展通过系统接口返回结果。例如 `NSExtensionContext` 保存扩展请求的上下文，扩展可以读取 `inputItems`，并通过 `completeRequest(returningItems:completionHandler:)` 结束请求、返回结果。这里的调用方可能是 Safari 等 host app，不一定是包含扩展的主 App。

XPC 是 Apple 提供的进程间消息与调用机制。进程 A 发送请求和参数，进程 B 执行工作并返回结果。在受支持的 ExtensionFoundation 扩展场景中，App 可以通过 `AppExtensionProcess` 建立与扩展的 XPC 连接。具体可用接口取决于系统版本和扩展类型。

不能笼统地认为 iOS 完全不支持 XPC，也不能将 macOS 中创建辅助服务的方式直接套用到任意 iOS App。使用系统扩展时，应优先通过该扩展类型规定的接口通信。

## 底层机制与共同限制

Mach 消息通过内核管理的端口传递数据。内核是操作系统管理进程、内存和权限的核心程序；Mach 端口是受发送、接收权限控制的消息端点。这里的端口不是网络连接使用的 TCP/UDP 端口号。

共享内存允许多个进程映射并访问同一块内存区域。共享内存与磁盘上的 App Group 共享目录是不同概念。Mach 消息、共享内存等机制都需要满足平台接口和权限要求，不能直接用于任意两个 App。

选择通信方式时，需要同时确定：双方是否属于同一开发团队、传递的是文件还是事件、是否需要持续连接，以及接收方是否正在运行。保存数据不会自动唤醒接收方；收到通知也不等于已经取得消息中的全部业务数据。
