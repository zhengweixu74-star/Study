# iOS 进程间通信与应用扩展

[返回笔记目录](../README.md)

## 进程间通信与访问边界

进程是操作系统为运行程序创建的运行实例，每个进程拥有独立的内存地址空间和资源。进程间通信（IPC）指不同进程交换数据或发送事件。一个进程中的普通 Swift 对象和全局变量位于本进程的地址空间，另一个进程无法直接访问。

沙箱是系统限制进程访问文件、资源和系统服务的机制。iOS App 能使用哪种通信方式，取决于双方的权限、系统版本、扩展类型和运行状态。共享数据、发送通知、建立连接和唤醒进程是四种不同的能力，一种通信方式通常只提供其中一部分。

| 方式 | 主要用途 |
| --- | --- |
| URL Scheme / Universal Links | 请求打开另一个 App，并传递少量参数 |
| App Groups | 加入同一 App Group 的 App 和扩展通过共享存储交换数据 |
| Darwin 通知 | 跨进程通知某个事件发生，常配合共享存储使用 |
| Keychain Sharing | 在具有相同访问组权限的 App 之间共享密码、令牌等凭据 |
| UIPasteboard | 在 App 之间传递用户复制、粘贴的内容 |
| Socket | 两个正在运行的进程之间直接发送和接收数据 |
| 系统扩展接口与 XPC | 在系统支持的扩展流程中传递输入、请求和结果 |

## App Extension 与主 App

App Extension（应用扩展）是随 App 一起安装的功能程序。系统在特定场景下运行 App Extension，让 App 在主 App 之外提供某项能力。主 App 是用户点击桌面图标后打开的完整应用。

| 扩展类型 | 作用 |
| --- | --- |
| 分享扩展 | 在其他 App 的分享界面中接收网页、图片或文件 |
| 小组件扩展 | 向主屏幕、锁定屏幕等位置提供小组件内容 |
| 通知服务扩展 | 在符合条件的远程通知展示前修改通知内容，或下载附件 |

以笔记 App 的分享扩展为例：

1. 用户在 Safari 中点击分享，并选择笔记 App 的分享操作。
2. 系统运行分享扩展，并向分享扩展提供网页链接等输入。
3. 分享扩展保存内容，并向系统报告本次任务完成。笔记 App 的主程序可以全程没有运行。

包含扩展、与扩展一起安装的 App 称为 containing app；发起扩展请求的 App 称为 host app。上例中，笔记 App 是 containing app，Safari 是 host app。

扩展代码运行在独立于主 App 的进程中。主 App 和扩展无法直接读取对方的内存变量，要通过共享存储或系统提供的通信接口交换数据。系统决定扩展何时启动、能运行多久、何时结束；扩展只在系统调起它的场景中运行。

Swift 的 `extension` 是为已有类型补充功能的语法。App Extension 是独立运行的功能程序，与 Swift 的 `extension` 只是名称相近。

## URL Scheme 与 Universal Links

URL Scheme 是 URL 中用于标识处理方式的部分，例如 `myapp://detail?id=123` 中的 `myapp`。App B 注册自定义 Scheme 后，App A 可以请求系统打开对应 URL；系统将 URL 交给匹配的 App，接收方解析参数并执行操作。

Universal Links 是与 App 建立关联的 HTTP/HTTPS 链接。开发者需要分别在网站和 App 中配置两者的关联。满足系统的打开条件时，系统把链接交给关联的 App；目标 App 未安装时，浏览器打开对应网页。

这两种方式适合打开目标页面并携带少量参数。例如接收方解析 `id=123` 后显示编号为 123 的详情。URL 跳转通常会切换到另一个 App，每次跳转只传递一次参数，不能在两个进程之间持续收发数据。接收方要校验传入的参数，例如检查 id 格式和取值范围。

## App Groups 与共享数据的存储位置

App Groups 是系统为同一开发团队的 App 和扩展提供的分组授权能力。加入同一个 App Group 的 App 和扩展可以访问这个组的共享容器。共享容器是系统为 App Group 单独创建的数据目录，只有组内成员可以访问。

通过共享文件、数据库和持久化配置交换的数据保存在磁盘上。App Group 共享目录独立于主 App 和扩展各自的私有数据目录；扩展只能访问共享目录，仍然无法访问主 App 的私有文件。

| 目录 | 通常的访问范围 |
| --- | --- |
| 主 App 的私有数据目录 | 主 App 可以访问；扩展不能直接访问 |
| 扩展的私有数据目录 | 扩展可以访问；主 App 不能直接访问 |
| App Group 共享目录 | 具有同一 App Group 权限的主 App、扩展或其他 App 可以访问 |

文件和数据库可以放入共享目录。程序调用 `FileManager.default.containerURL(forSecurityApplicationGroupIdentifier: "group.com.example.app")` 获取共享目录的 URL；系统分配的磁盘路径可能变化，代码中不写死路径。当前 App 或扩展已正确配置这个 App Group 时，调用才返回 URL；返回值是可选值，配置不正确时为 nil。

少量配置可以通过 `UserDefaults(suiteName: "group.com.example.app")` 读写这个组的共享配置。主 App 和扩展都要使用同一个已授权的组标识。`UserDefaults.standard` 是各进程自己的私有配置，双方写入 `UserDefaults.standard` 的值互相看不到。

共享配置是两个进程分别读写同一份磁盘数据，各进程持有自己的 UserDefaults 对象。UserDefaults 可能先缓存写入、再异步写入磁盘。因此一个进程设置值后立即发送通知，另一个进程收到通知时，可能还读不到新值。

例如，分享扩展把图片保存到共享目录。用户之后启动主 App，主 App 从同一个目录读取图片，此时分享扩展不需要运行。多个进程同时修改同一份文件或数据库时，需要协调读写，否则可能相互覆盖，或读到写了一半的内容。

## Darwin 通知与共享存储的配合

Darwin 通知是跨进程的事件通知。进程 A 发布一个通知名称；订阅了这个名称的进程 B 正在运行时收到事件，并执行已注册的回调。回调是接收方预先注册的函数或闭包，通知到达时由通知中心调用。

通过 `CFNotificationCenterGetDarwinNotifyCenter()` 发送的 Darwin 通知只有通知名称，`userInfo` 会被忽略，无法携带业务数据。常见做法是先保存共享数据，再发送“数据已更新”的通知；接收方收到通知后，重新读取共享存储。

1. 进程 A 按所用存储机制的规则写完共享数据，确保读取方能读到完整数据。
2. 进程 A 发布双方约定的 Darwin 通知名称。
3. 正在运行的进程 B 收到通知后，从共享存储读取当前状态。

系统不保存 Darwin 通知，也不保证每次发布都单独送达。Darwin 通知不会唤醒被系统挂起的 App，也不会启动已经结束的 App。所以主 App 每次启动或回到前台时，都要主动读取一次共享状态。

`NotificationCenter.default` 只在当前进程内传递通知。两个进程使用相同的通知名称，也只是各自进程内的两个独立通知。

## Socket、文件系统路径与实际数据传递

Socket 是操作系统提供的数据收发端点。端点是进程用于发送或接收数据的通信对象。双方通过 Socket 传递字节，再按照事先约定的格式解释这些字节。

UNIX domain socket 用于同一设备内的进程通信。本节讨论用文件系统路径标识的 UNIX domain socket。在 iOS App Group 场景中，这个路径要位于组内成员都能访问的共享目录。

路径示例为 `<App Group 共享目录>/ipc.sock`。这个路径是通信入口在文件系统中的地址；`ipc.sock` 是标识 Socket 的特殊文件条目。扩展通过这个地址找到主 App 的 Socket 并发起连接。

以需要建立连接的流式 Socket 为例，流式表示双方收发的是连续字节序列：

1. 主 App 创建 Socket，并调用 `bind`，传入包含共享目录路径的地址，将 Socket 与该地址关联。
2. 主 App 调用 `listen`，允许其他进程向这个 Socket 发起连接。
3. 扩展创建自己的 Socket，调用 `connect` 并传入同一个地址。操作系统根据路径找到主 App 的 Socket。
4. 主 App 调用 `accept` 接收连接，并获得用于本次连接的 Socket。连接建立后，双方通过连接对应的 Socket 发送和接收数据。

Socket 路径只用于找到通信对象。通过 Socket 发送的消息由操作系统在内存中传递，不写入 `ipc.sock` 文件。共享目录只提供地址所在的位置和访问权限。

| 比较项 | 共享普通文件 | UNIX domain socket |
| --- | --- | --- |
| 路径的含义 | 定位保存数据的文件 | 定位用于连接的通信入口 |
| 数据传递方式 | 发送方写文件，接收方读文件 | 双方通过 Socket 发送、接收字节 |
| 数据是否保存在该路径对应的普通文件内容中 | 是 | 否 |
| 发送方结束运行后能否再读取先前数据 | 文件仍存在且可访问时可以 | 不能；Socket 不保存已发送的消息 |

收发数据时，双方进程都必须正在运行。iOS App 进入后台后，系统通常会挂起 App，已建立的 Socket 连接不能阻止挂起。`ipc.sock` 文件条目在进程结束后可能仍然存在，所以路径存在时，主 App 进程和连接可能已经失效。

## 凭据共享、剪贴板与系统扩展接口

### Keychain Sharing

Keychain 是系统提供的敏感数据存储服务。钥匙串访问组规定哪些 App 可以访问某个钥匙串条目。同一开发团队的 App 配置相同的访问组后，可以共享属于该组的密码、令牌或密钥。

例如 App A 把登录令牌写入共同的访问组，App B 配置了同一访问组后读取这个令牌。Keychain Sharing 适合共享凭据；频繁传递的普通业务数据应使用其他方式。

### UIPasteboard

`UIPasteboard` 是访问系统剪贴板的接口。App A 写入文本、链接或图片，App B 读取这些内容。剪贴板适合用户主动复制、粘贴。剪贴板内容会被后续的复制操作覆盖；App 读取其他 App 写入的内容时，系统可能向用户弹出授权提示。所以剪贴板只适合用户触发的一次性传递，不适合持续、自动的通信。

### NSExtensionContext 与 XPC

分享扩展等扩展按系统规定的流程工作：调用方提供输入，扩展通过系统接口返回结果。例如 `NSExtensionContext` 保存扩展请求的上下文。扩展读取 `inputItems` 取得输入，再调用 `completeRequest(returningItems:completionHandler:)` 结束请求并返回结果。这里的调用方是 Safari 等 host app，可以是 containing app 以外的任何 App。

XPC 是 Apple 提供的进程间消息与调用机制。进程 A 发送请求和参数，进程 B 执行工作并返回结果。iOS 在部分场景中支持 XPC：在受支持的 ExtensionFoundation 扩展场景中，App 可以通过 `AppExtensionProcess` 建立与扩展的 XPC 连接。具体可用接口取决于系统版本和扩展类型。

macOS 中创建 XPC 辅助服务的方式，iOS App 一般无法直接使用。使用系统扩展时，优先使用该扩展类型规定的接口通信。

## 底层机制与共同限制

Mach 消息通过内核管理的端口传递数据。内核是操作系统中管理进程、内存和权限的核心程序；Mach 端口是内核管理的消息端点，进程持有发送权或接收权才能向端口发送或从端口接收消息。Mach 端口与网络连接使用的 TCP/UDP 端口号无关。

共享内存允许多个进程把同一块物理内存映射到各自的地址空间并访问。共享内存位于内存中，App Group 共享目录位于磁盘上。Mach 消息、共享内存等机制都受平台接口和权限限制，只能在系统允许的进程之间使用。

选择通信方式时，需要同时确定四件事：双方是否属于同一开发团队、传递的是文件还是事件、是否需要持续连接、接收方是否正在运行。一方保存数据后，接收方不会因此被唤醒；接收方收到 Darwin 通知后，还要读取共享存储才能取得业务数据。
